## What this is
Multi-user Telegram assistant "Sydney" (repo name `melissa-bot`): tasks, finance/debts, calendar, Gmail triage, morning/evening briefs. Node, long-polling (no webhook), OpenAI tool-calling into MCP child processes. Core constraint: multi-tenant behavior sits on top of a single-tenant Task Dashboard, so per-user isolation is enforced in app code, and only one process may poll the Telegram token at a time.

## Architecture
Repo files:
- `melissa.js` -> deployed as `/opt/melissa/whatsapp-bot/whatsapp-bot.js`. Bot loop, onboarding, per-user routing/isolation, OpenAI tool orchestration, cron briefs, SELFCHECK.
- `db.js` -> SQLite (`node:sqlite`) users + invite_codes + debts. Debts isolated by `WHERE user_id=?`.
- `sheets-mcp.js` -> Networking Google Sheet MCP (Santiago-only feature today).
- `categories.json` -> task categories.
- `ops/deploy-melissa.sh`, `ops/melissa-bot.service`, `ops/README.md` -> production runtime, version-controlled.

Server-only (NOT in repo, edit on VM): `/opt/melissa/.openclaw/skills/tasks-mcp.js` (Task Dashboard MCP; has the `overdue_today_tomorrow` filter + path parameterization) and `calendar-mcp.js` (Google Calendar/Gmail MCP). Mirror any change to `/root/.openclaw/skills/*` for rollback parity.

Load-bearing ideas:
- Task ownership = `[uid:CHATID]` tag inside the task title; Santiago's tasks are untagged. Reads filtered by `filterTaskOutput`; writes/deletes gated by `ownedTaskIdSet` (fail-closed).
- Brief markers (`🔴` priority, `🔜` tomorrow) are emitted by the tool output; the model preserves them, never invents them.
- Paths are env-parameterized (`DB_PATH`, `CFG_PATH`, `CATS_PATH`, `USAGE_LOG`, `PRIORITY_FILE`, `SKILLS_DIR`) with `/root` defaults; the systemd unit points them at `/opt/melissa`.

No build step. `npm install --omit=dev` only.

## Key decisions (do not relitigate)
- **Deploy branch is `pause-morning-brief`**, not `main`. `deploy-melissa.sh` defaults to it. `main` is the nominal default and lags; keep it synced via PR.
- **Non-root migration used dry-run SELFCHECK -> fast cutover -> retained rollback**, because two pollers can't share one bot token (409). Root service kept disabled, not deleted, until stable.
- **`RestrictSUIDSGID` omitted** from the unit: VM is systemd 239, that directive needs >=242.
- **Google multi-user (Calendar/Gmail) deliberately deferred.** Today the MCP servers boot with Santiago's single OAuth token, so enabling `calendar`/`email` for another user would expose Santiago's own account. Must be per-user OAuth (token per call) before rollout. Do not flip those feature flags for invited users.
- **`tasks-mcp.js`/`calendar-mcp.js` are server-managed** by design (not shipped by the deploy script).
