**3. Phase 1 — Telegram actually renders now** (`f45f983` and the commit before it)

Root cause of the "ugly briefs": **`sendMessage` never passed `parse_mode`.** `parse_mode` appeared
zero times in the file. Every `*bold*` the bot wrote — the whole brief, every onboarding message —
reached users as literal asterisks.

- Messages now render as **HTML**, not Markdown. HTML needs only `& < >` escaped; Markdown breaks on
  any stray `*`, `_` or `[` inside a user's own task title and makes Telegram reject the message.
- `toTelegramHtml()` escapes everything first, then reopens only the tags the bot emits, so user
  content can never introduce markup.
- The italic rule is deliberately narrow: `_` only pairs at word edges, so `America/Los_Angeles` and
  `America/New_York` in one message are **not** turned into italics. There is a regression test for
  exactly this.
- **Plain-text fallback:** if Telegram still rejects a message, it is resent without `parse_mode`
  rather than lost.
- Chunking splits on line boundaries, never mid-tag (the old code sliced blindly at 4000 chars).
- `/users` and `/invite` use `<code>` spans instead of backticks, which never rendered.

**5. Phase 1 — the voice-path defect from the last handoff is FIXED**

Neither `tgRequest` nor `downloadFile` had a timeout, and Node's `https` has no default, so a stalled
Telegram call wedged that chat's FIFO queue until a restart.

- `tgRequest` takes a per-call deadline, default 20s. `getUpdates` passes 45s so long-polling still
  works — this is the trap to remember if you touch it.
- `downloadFile` has a 30s deadline, checks the status code, and cleans up the partial temp file.
- The Whisper call gets an `AbortSignal` (60s); it had no per-call deadline either.

`VOICE_PROMPT_ES` is still unused. The blocker named in the 2026-08-26 handoff — "safe to re-enable
once those have timeouts" — **is now cleared**, so rewiring it is a clean next step.

Two traps this hit, worth knowing before touching Vercel again:

- **Environment variables only take effect on a rebuild.** `NEXT_PUBLIC_*` are inlined at build
  time; the server-side ones need a redeploy too. A first attempt (`…-six-snowy…`) built without
  them and is permanently frozen in that broken state — it still returns 401 to the bot today.
- **Google Sign-In breaks on a new URL** until that exact origin is added to the *Authorized
  JavaScript origins* of the **web** OAuth client `…-p82fvab9n0fkdou4nevr0na7k8q9jbs3`. The other
  client in that Google project is the bot's, and must not be touched.
